# ThaiNative — Asset & UI direction v1

สถานะ: แผนตั้งต้น; ชุด v1 ลงเกมแล้ว ดูรายการที่ทำจริงและข้อจำกัดใน `ASSET-DELIVERY.md` ตัวเลขเฟรมและระบบใหม่ด้านล่างเป็นเป้าหมายของแผน ไม่ใช่ทั้งหมดที่ส่งมอบแล้ว

## แนวภาพ

Chibi ภูติไทยในโลกนิทาน: รูปร่างกลม อ่านง่าย เส้นขอบม่วงเข้ม แสงจากซ้ายบน
วัสดุหลักคือกระดาษสมุดข่อย ผ้าฝ้าย ไม้ เครื่องปั้นดินเผา และทองประดับลายไทยแบบเรียบ
สีหลัก: ม่วง #30283F, ทอง #E6BE76, หยก #89D8BD, กระดาษ #FFF0D5, ปะการัง #ED8D87
ใช้ลายไทยตามขอบและมุม เว้นพื้นที่ข้อความและตัวเลขให้โล่ง
อักขระบนของวิเศษเป็นสัญลักษณ์แฟนตาซีที่ออกแบบใหม่

## Character sheet

เริ่มจาก model sheet: หน้าตรง ด้านข้าง และสามส่วนสี่ พร้อมสัดส่วน 2–2.5 หัว
กำหนดจุดเท้า origin, จุดถืออาวุธ และจุดปล่อยกระสุนก่อนทำแอนิเมชัน

| ท่า | จำนวนเฟรมเป้าหมาย | จังหวะ |
| --- | --- | --- |
| Idle | 6 | หายใจ/โยกเบา ๆ ไม่รบกวนการเล็ง |
| Move | 8 | ก้าวสั้น เท้าสัมผัสพื้น ไม่ไถล |
| Aim | 1 pose + อาวุธแยก | ปรับองศาอาวุธตามมุมยิงจริง |
| Cast | 6 | เตรียม → ปล่อยกระสุน → คืนท่า; ผูก event ที่เฟรมปล่อย |
| Hit | 3 | สะดุ้งสั้น คงตำแหน่งชนที่เซิร์ฟเวอร์กำหนด |
| Guard | 4 | ยกยันต์แล้วค้างท่า |
| Victory | 6 | กระโดด/ยิ้ม ไม่วนตลอดเวลา |
| Defeat | 5 | นั่งหมดแรง ให้เข้ากับโทนน่ารัก |

เริ่มทดลองเฟรม 256 × 256 px; ตรวจอาวุธและเครื่องประดับไม่หลุดกรอบก่อนล็อกขนาด
อย่าฝืนยัดทุกท่าลงชีตเดียว: แยก action และใช้ metadata fps/loop/event
ตัวละครแต่งตัวได้ควรแยกอาวุธกับของสวมใส่ที่เปลี่ยนจริง ก่อนขยายจำนวนชุด
ท่าทางเป็นภาพแสดงผล; collision, damage และตำแหน่งจริงยังมาจาก server

## UX/UI เมนู

| เมนู | โครงหน้าที่เสนอ | สิ่งสำคัญต่อผู้เล่น |
| --- | --- | --- |
| Lobby | NPC เป็นทางเข้า เมนูล่าง 5 หมวด: ตัวละคร, กระเป๋า, ตีบวก, ประลอง, ผจญภัย | ปุ่มผจญภัยเด่นที่สุด; ร้าน/แต่งตัวเข้าผ่าน NPC |
| ตัวละคร/อุปกรณ์ | ตัวละครซ้าย ช่องสวมใส่ใกล้ตัว รายการไอเทมขวา | เทียบค่าปัจจุบัน → หลังเปลี่ยน ใช้เครื่องหมาย +/− ร่วมกับสี |
| กระเป๋า | แท็บอาวุธ/เกราะ/เครื่องราง/ทั้งหมด กริดไอเทม รายละเอียดเมื่อเลือก | มีตัวบอกสวมใส่ จำนวน และ + โดยแยกชั้นกับภาพ |
| ตีบวก | อาวุธกลาง วัตถุดิบ/เงินด้านล่าง ค่าพลังก่อน–หลัง | แสดงโอกาสสำเร็จและสิ่งที่เสียก่อนกด; ล็อกปุ่มระหว่างรอผล |
| ร้านค้า | รูป ราคา รายละเอียด เทียบของที่ใส่อยู่ | ปุ่มซื้อแสดงราคาอีกครั้ง; เงินไม่พอบอกจำนวนที่ขาด |
| แต่งตัว | พรีวิวตัวละคร + ชุดที่เป็นเจ้าของ | แยกค่าพลังออกจากรูปลักษณ์; แสดงราคาและสถานะปลดล็อก |
| ผจญภัย | 3 ด่านเป็นเส้นทาง + แท็บคนเดียว/ทีม | เห็นศัตรูและรางวัล; ทีมเห็นกำลังรอและปุ่มยกเลิก |
| PvP | เลือกโหมด → รอคู่ → เข้าสนาม | บอกค่าพลังถูกปรับเท่ากัน และต้องมีผู้เล่นอีกคน |
| Battle HUD | HP/อาคม, มุม/แรง, สกิล, ปุ่มยิง; แชทย่อมุม | พื้นที่เล็งโล่ง; ทิศลม เวลา และเทิร์นอ่านทันที |
| ผลการต่อสู้ | ผลชนะ/แพ้ รางวัล EXP เล่นอีกครั้ง/กลับหมู่บ้าน | รางวัลตรงข้อมูล server และรับซ้ำไม่ได้ |

Mobile: แสดงรายการก่อน แตะแล้วเปิดรายละเอียดเป็นแผงด้านล่าง
Desktop: ใช้รายการและรายละเอียดคู่กัน; ปุ่มหลักไม่ย้ายตำแหน่งเมื่อเปลี่ยนไอเทม
ทุกหน้าต้องมี loading, empty, error, disconnected และ pending state ตามการใช้งานจริง
รองรับคีย์บอร์ด, focus ที่เห็นได้, Escape ปิด modal, คืน focus ให้ปุ่มต้นทาง และ reduced motion
ทดสอบข้อความไทยยาวและ touch target เป้าหมายอย่างน้อย 44 × 44 CSS px

## ระดับไอเทมที่เสนอ

C เทาหิน / B เขียวหยก / A ฟ้า / S ม่วง / SS ทอง
แสดงตัวอักษรร่วมกับสีเสมอ; rarity ไม่ใช่ระดับตีบวก และไม่ควรใช้แทน tier ความเก่งของตัวละคร
เก็บเป็น metadata เมื่อเพิ่มระบบจริง ปัจจุบันอุปกรณ์ยังไม่มี rarity

## ชุดงานที่ควรลงมือถัดไป

นำ 9 ภาพที่รองรับระบบเดิมเข้าเกม + ปรับกระเป๋า/อุปกรณ์เป็นหน้าตัวอย่างที่ใช้งานได้
จากนั้นขยาย component เดิมไปหน้าตีบวก ร้าน และแต่งตัว ก่อนผลิตชีตตัวละครทั้งชุด
ยังไม่เพิ่มปุ่มกาชา กิลด์ หรือระบบไอเทมใช้แล้วหมด จนกว่าจะมีระบบและกติกาที่รองรับ
